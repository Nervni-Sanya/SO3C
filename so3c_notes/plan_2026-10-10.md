| | (a) resume `headline60` to 120 epochs | (b) fresh 60 vs 120 epochs, K=32 long, 2 seeds each |
|---|---|---|

| K | **64**, the headline | 32: the width effect did not transfer from 32 to 64 |
| GPU-h | **8.6** (one session) | **21** |
| by-product | if it pays, a new best single model and a fifth ensemble member | the 60-epoch runs double as the same-stack K=32-long controls every later long-schedule test needs |

**Recommendation: (a), the 60 → 120 continuation only (8.6 h).**
- (b) would spend 70% of the window on a question whose plausible answer, +0.0001–0.0003, cannot close a 0.003 gap. It would also answer at the wrong K.
- 60 → 90 on top of 60 → 120 adds 4.3 h for a midpoint that a single seed cannot resolve.

**Technical details.**
- The checkpoint `results_k64/headline60/checkpoints/…seed0.pt` (epoch 60, torch 2.10) is **embedded** in the notebook, about 455 KB of base64. That does not depend on the 2026-09-20 kernel's output still existing.
- Run with `--epochs 120 --resume --keep-best` into a new results directory. `--resume` skips models whose result JSON already exists.
- The CUDA RNG state was saved under 2.10. If 2.11 rejects it, the kernel fails within minutes. The fallback drops `cuda_rng` from the copy: a continuation needs no reproducible batch order.
- `--max-seconds 39000`; a finish kernel is prepared but not pushed.

**Decision rule** (on the final weights, against epoch 60 of the same model):

| result | decision |
|---|---|
| ΔAUC ≥ +0.0003 **and** final val loss < 0.16276 | longer training pays at K=64. 120 epochs becomes the headline schedule; the model joins the ensemble; fresh 120-epoch seeds go to the next window |
| ΔAUC ≤ +0.0001 | training length is exhausted near 60 epochs for this architecture. Close |
| in between | unresolved; record it, no follow-up unless quota would otherwise sit idle |

`--keep-best` also reports the best-validation weights. The rule uses the final weights; the best-validation ones are a cross-check.

## 3. Representation screen

The probe protocol (K=32, 400k training jets, 20 epochs, `--compile`), T4 with torch 2.11.0+cu128 pinned and asserted, seeds 0–2 per arm.

**Candidates, with verdicts**

| candidate | verdict | why |
|---|---|---|
| **R1. `beam_energy`** = 0.02, about 1 GeV at the K=32 scale of 46.96 GeV, against the default 1.0 (about 47 GeV) | **run** | Never tuned. PELICAN feeds (1,0,0,±1) in GeV and LorentzNet √2 GeV, both with log compression. The value sets the asinh regime of ⟨p,b±⟩ in `h_init` and of asinh⟨P,b±⟩ in the readout. It also sets the beam nodes' soft bound 1+⟨b,P⟩. **Measured** on 20k training jets at K=32: ⟨b±,P⟩ spans 2.0–80 at E_b = 1 (median 12, so the bound is saturated) and 0.04–1.6 at 0.02. The per-constituent ⟨p,b±⟩ spans 0.004–7.5 at E_b = 1 (median 0.17), so asinh sits partly in its log range; at 0.02 it would be entirely linear. The beams are the one input that paid (+0.0023), but scale knobs measured null in the log-knee arm. Prior 0 to +0.0002, parameter-free. An optional second value, E_b = 50, pushes the other way |
| **R2. Lab-frame kinematic scalars in `h_init`**: log E, log pT, log E/E_J, log pT/pT_J, y − y_J, \|Δφ_J\|, ΔR_J (ParT's particle features) | **run** | All are functions of invariants of {p, P, b±}, so covariance with the beams moved along is exact. L-GATr Table 3: these features alone reach 0.9869 against 0.9846 without references, but they add nothing on top of references (0.9870). LLoCa Table 6 (JetClass): non-invariant scalars 0.9881 against reference vectors 0.9877, both together 0.9882. We already have the beams, so prior 0 to +0.0003 |
| **R3. Lab-frame pair features on the edges**: ln Δ_ab, ln k_T,ab, ln z_ab, ln m²_ab (ParT's interaction features) | **run** | ParT's own ablation (JetClass, Table 1): +0.0018 AUC from pair features, but that is against no pair input at all. Ours already has pair invariants; the new thing is their lab-frame, log-scaled form. Pairs that involve a beam are masked. Prior 0 to +0.0003; about 1.1× cost |
| compression of the pair invariants (asinh after global RMS scaling) | do not rerun | log knee: ΔAUC +0.00000 ± 0.00008 (measured) |
| the jet-axis component the lift drops | closed | For massless constituents the lift loses nothing (gap_thesis §3.2). Vector channel −0.00002 paired, same stack at the time |
| parity-odd information | closed | The data are parity-symmetric. The squares of parity-odd invariants are Gram determinants of bilinears. The model is already nearly parity-invariant: σ_x changes logits with std 0.015, and TTA gives +0.00002 (measured) |
| boost to the rest frame first (numerics) | dropped | float32 vs float64: ΔAUC +1.4e-7 (measured today) |
| jet-frame Hermitian norm (A), unitary channel mixing (D) | not run | Both target the edge saturation; halving it moved nothing (edge-norm arm) |
| moment tensors (B) | not run | Jet-level stacking null (gap_generic_ml §8.4) |

**Control.** Reuse the 2026-10-05 control (`results_message/probe_screen/base`, torch 2.11.0+cu128, T4) if the card still has that build and a **pairing check** passes:
- The first screen kernel starts with a 2-epoch rerun of control seed 0 (about 5 minutes).
- It compares the epoch-1 and epoch-2 training and validation losses with the stored history.
- Agreement within 1e-5 is a pass.
- Differences of 1e-4 or more, or anything in between, mean a fresh control kernel (1.4 h) is pushed before the arms are read.
- From now on every result also records a batch-order fingerprint (C2), so later pairings can be checked directly.

**Decision rule per arm**, three paired seeds against the control (the 10-05 screen's paired sd was 0.00008–0.00010):

| result | verdict |
|---|---|
| mean ΔAUC ≥ +0.00015 **and** all three seeds > 0 | **promote** to the K=32 long schedule |
| \|mean ΔAUC\| < 0.0001, or mixed signs | **close** at the probe level |
| otherwise | unresolved; no promotion unless quota would sit idle |

Rejection at 30% is reported but never decides on its own. In the 10-05 screen both arms moved it about 5% in opposite directions while AUC stayed within ±0.00004.
